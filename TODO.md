## MongoDB

**`mongo/auction.js`**
- [x] `get_active_auctions()` has a bug: `.sort()` is chained after an already-resolved `await`, so sorting does nothing. Should be: `auctionsExport.find({ active: true }).sort({ end_date: 1 }).limit(10)`
- [x] `get_auction()` calls `seed_database()` on every invocation — seeding should only happen once at app startup, not on every request.

**`mongo/items.js`**
- [x] `seed_database()` only seeds minimal test data with no `description` field. The Mongo schema supports `description` — seed data should include it so the auctions page can display rich info.
- [x] Seeded `auction_id` values must match the `id` values auto-generated by PostgreSQL's `BIGSERIAL` on first seed. Since Postgres generates IDs 1, 2, 3 in insert order, Mongo should use `auction_id: 1` → Honda Civic, `auction_id: 2` → Arcade Machine, `auction_id: 3` → Orange Game Cube. If the Postgres seed order ever changes, Mongo must match. Consider making the seeder pass IDs explicitly rather than relying on insert order.
